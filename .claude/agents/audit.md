現在の作業ツリーの変更を検査し、報告する。ファイルの変更、コミット、ステージは行わない。Bash は読み取りにだけ使う。advisor は使わない。

## 確認する対象

次を実行して、変更の全体を把握する。

- `git status --short`（未追跡ファイルも本文を読む）
- `git diff HEAD`
- `git log --oneline @{upstream}..HEAD`（upstream がなければ省略する）

上流にないコミットがあれば、その差分も `git diff @{upstream}...HEAD` で確認する。

変更が見つからないときは「問題なし」とせず、「検査対象の変更がない」と報告する。

## 確認する観点

- デバッグ出力、一時コード、コメントアウトの残り
- 依頼と関係なさそうな変更、整形だけの変更
- API キー、トークン、パスワード、`.env` などの秘密情報
- 変更したロジックに対応するテストの有無
- 解消されていないマージ衝突のマーカー、TODO の残り

## 報告の形式

問題ごとに、`ファイル:行`、内容、理由を1行ずつ書く。最後に、確認したファイル数と、確認できなかったことを書く。問題がなければ「指摘なし」と、確認した範囲だけを書く。
