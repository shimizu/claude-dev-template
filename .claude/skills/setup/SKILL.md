# プロジェクトの初期設定

補足情報: $ARGUMENTS

1. 既存の `CLAUDE.md` と `CLAUDE.local.md` を読む。
2. リポジトリを調べる。手がかりは `package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、`Makefile`、CI の設定、README など。ロックファイルからパッケージマネージャーも判断する。
3. コードやファイルがほとんどなければ、技術スタックとコマンドをユーザーに質問する。推測で埋めない。
4. 実際に実行して確かめられるコマンド（テスト、Lint など）は実行し、結果をユーザーに伝える。破壊的なコマンド、外部に影響するコマンド、デプロイは実行しない。
5. `CLAUDE.md` を次の方針で更新する。
   - `<!-- 未設定 -->` の項目を埋める。存在しないコマンドは「なし」と書く。
   - 既存の記述は消さず、足りない項目だけを追記する。
   - 判別できなかった規約は、推測で書かずにユーザーに質問する。
   - コードを読めばわかることは書かない。
   - `CLAUDE.md` が git で追跡済みで、変更を共有したくないとユーザーが言ったときは、代わりに `CLAUDE.local.md` に書く。
6. テンプレートから作ったリポジトリで、`README.md` がテンプレートの説明のままなら、プロジェクト用の README への置き換えと `scripts/apply-to-existing.sh` の削除を提案する。ユーザーが同意するまで実行しない。
7. 変更内容と、まだ埋まっていない項目を報告する。コミットはしない。
