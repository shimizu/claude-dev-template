# 機能の開発

作るもの: $ARGUMENTS

内容が空なら、作りたいものをユーザーに質問する。

コマンドと規約は `CLAUDE.md` または `CLAUDE.local.md` に従う。

1. **調査する。** まだファイルを編集しない。関係する範囲が広いときは Explore サブエージェントで調べ、既存の実装、規約、再利用できるコードを把握する。
2. **計画を立てる。** 変更するファイル、手順、テストの方法、やらないことを短くまとめる。要件を決めるのに必要な情報が足りなければ質問する。
3. **方針を相談する。** 計画を固める前に advisor に相談し、指摘を計画に反映する。
4. **合意を取る。** 計画をユーザーに示し、承認を得てから実装する。数ファイル程度の明快な変更なら、計画を示してそのまま進めてよい。
5. **小さく実装する。** 手順ごとに、該当するテストを追加して実行する。依頼にない機能は足さない。同じエラーが2回続いたら、繰り返さずに advisor に相談する。
6. **報告する。** 実装した内容、計画から変えた点、確認の結果を伝え、`/finish` を提案する。コミットはしない。

advisor を使えないセッションでは、その旨を一度だけ伝えて続ける。
